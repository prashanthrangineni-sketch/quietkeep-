# AG-04: Phase-2 proof kit (the founder's field-test screen)

## Summary

Builds the Drive Phase-2 proof kit field-test screen and pure evaluation engine. When the OBD reader hardware arrives, the founder runs each test from a single screen (`/drive/proof`) and stores verification evidence in Supabase (`public.drive_proof_runs`) for Claude to verify.

### Checklist Steps Implemented:
1. **Reader genuine**: Vgate updater recognised it (yes/no + note).
2. **Desk test**: tilt in test mode → sealed black-box record appears (`list()` from `src/lib/blackbox.js`).
3. **Parked car reader**: connect + "Read car now" (snapshot with rpm and voltage arrived).
4. **"How is my car?" by voice**: manual yes/no for spoken summary.
5. **Proof ride**:
   - 5a. Three firm brakes (count new `ride_road_events` rows for user in last 30 min ≥ 3).
   - 5b. Staged fall check-in appeared (manual yes/no).
   - 5c. "Save last 60" produced record with `obd_samples > 0` (parses JSON header of `.qkedr` packet).
6. **Speed check**: runs `compareSpeeds` from `src/lib/obd/blackbox-feed.js` on OBD and GPS samples, pass if `maxDiffKmh ≤ 1`.
7. **Speed rule**: while moving, ask to pay someone → "I'll do that when you stop" (manual yes/no).
8. **Indicator**: turn and leave indicator on → "Your indicator is still on" (manual yes/no, listening ON).

## Files Created
- `src/lib/proof-kit.js`: Checklist definition, pure evaluation functions for automatic steps, `.qkedr` packet & header parsing, binary GPS decoder, Supabase persistence helpers.
- `src/app/drive/proof/page.jsx`: Dedicated unlisted field-test screen at `/drive/proof` with Run / Pass / Fail / Skip buttons, notes inputs, evidence boxes, and "Copy summary" button.
- `tests/proof-kit.test.mjs`: Unit test suite testing every evaluator with pass, fail, and missing-data inputs (71 tests).
- `supabase/migrations/20261020_drive_proof_runs.sql`: Migration for `public.drive_proof_runs` table with RLS select/insert policies (append-only).
- `docs/drive/proof-kit.md`: Technical documentation of checklist, evaluation rules, schema, and operation.
- `docs/drive/pr-bodies/AG-04.md`: PR description.

## Operational Constraints & Limits
- Unlisted route `/drive/proof`; not linked from any public screen or navigation.
- Database migration `supabase/migrations/20261020_drive_proof_runs.sql` is committed as a file only; NOT applied to production per rule 37.
- Evaluators never invent a pass; any missing or invalid data results in explicit failure with failure reason.
- Read-only queries for evidence verification (`ride_road_events`, `listBlackboxRecords`).
