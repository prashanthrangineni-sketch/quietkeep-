# AG-05: Play declarations update (DRV-09b, docs only)

## Summary

Updates the Google Play Console release declarations and justifications in `docs/play-release-declarations.md` for upcoming Drive Mode production release submission, adding declarations in the established style of Section F and Section A2 for:
1. **Indicator listening (`IndicatorEar`, DRV-11)**:
   - Microphone permission justification line for Play Console.
   - Operating rules: strictly opt-in, default OFF; short bounded listens (5–8s) only while Drive Mode is open on screen; never continuously listening; no foreground service.
   - Data Safety: sound is reduced on the phone to loudness/energy numbers (100 fps) and immediately discarded; raw audio is never stored, written to disk, or transmitted to any server. Data safety declaration: **Audio NOT collected**.
2. **Car reader (OBD-II vehicle diagnostics, DRV-06 / AG-02)**:
   - Bluetooth permissions (`BLUETOOTH_SCAN` with `neverForLocation` flag and `BLUETOOTH_CONNECT`).
   - Read-only guarantee: Mode 04 (clear codes) and non-volatile memory AT commands structurally blocked in code (`assertReadOnlyCommand()`).
   - Data minimization: Telemetry remains on device; no data leaves the phone except the user's optional vehicle record (`public.vehicles` table) in their private Supabase account.
3. **Phase-2 field test proof runs (`public.drive_proof_runs`, AG-04)**:
   - Data safety entry for user-owned test verification runs performed at unlisted route `/drive/proof`.
   - Stored in `public.drive_proof_runs` under PostgreSQL Row-Level Security (RLS) policies (`drive_proof_runs_owner_select` and `drive_proof_runs_owner_insert` enforcing `auth.uid() = owner`).
   - Append-only table, cascading delete on user account deletion.

No other existing sections in `docs/play-release-declarations.md` were modified.
